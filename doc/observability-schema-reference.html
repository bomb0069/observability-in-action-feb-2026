Section 02
Log Schema
Structured JSON only — Unified format with log_type discriminator
Concept: Base fields + log_type + type-specific fields
ทุก log มี base fields เหมือนกัน — log_type บอกว่า fields อะไรจะตามมา ไม่ต้องแยก index หลัก ยกเว้น Audit (compliance)
Base: timestamp · level · service · version · env · trace_id · span_id · log_type · msg

error

  • error.code
  • error.message
  • error.type
  • error.stack
  • context {}

business

  • event
  • entity_type
  • entity_id
  • actor_id
  • metadata {}

state_change

  • entity_type
  • entity_id
  • changed_by
  • before {}
  • after {}
  • changed_fields

audit

  • actor_id
  • action
  • resource_type
  • resource_id
  • result
  • ip_address

external_call

  • provider
  • operation
  • result
  • duration_ms
  • provider_ref
  • error_code
Audit logs
ต้องแยก stream — WORM policy (Write Once Read Many) + จำกัด access เฉพาะ security/compliance team เท่านั้น ใช้ Loki separate stream หรือ Elastic index แยก
Base fields — ทุก log entry ต้องมี
timestamp
Required
ISO8601 UTC · 2026-03-15T10:23:45.123Z · ไม่ใช้ Unix timestamp
level
Required
error / warn / info / debug · lowercase เท่านั้น · ห้าม ERROR
msg
Required
Human-readable summary · ห้าม interpolate variable ใน msg
service
Required
payment-service · kebab-case · ต้องตรงกับ Trace resource
version
Required
1.4.2 · semver เท่านั้น
env
Required
prod / staging / dev · 3 ค่าเท่านั้น · ห้าม staging2, dev2
trace_id
Required
สะพานไป Trace · 128-bit hex · จาก active span context
span_id
Required
64-bit hex · จาก active span · drill down ใน trace
log_type
Required
error / business / state_change / audit / external_call
request_id
Optional
idempotency key ถ้ามี
host
Optional
Pod / hostname · pod-abc123
namespace
Optional
k8s namespace · สำหรับ k8s deployment

Log level usage guide
Levelใช้เมื่อProduction volumeตัวอย่าง
errorเกิดเหตุการณ์ที่ต้องการ action ทันที + ต้องมี full context< 0.1%payment_failed, db_connection_lost
warnผิดปกติแต่ยัง recover ได้ / retry สำเร็จ< 1%retry_succeeded, rate_limit_near
infoBusiness events ที่มีความหมาย เท่านั้นปานกลางorder_placed, user_signup
debugปิดใน prod — เปิดเฉพาะตอน debugปิดใน prodcache_miss, sql_query_plan

// middleware / interceptor (ทำครั้งเดียว) const span = trace.getActiveSpan(); const ctx = span.spanContext(); logger.setContext({ trace_id: ctx.traceId, span_id: ctx.spanId, service: SERVICE_NAME, env: ENV });
